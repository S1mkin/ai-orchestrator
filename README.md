# ai-orchestrator

Личный конвейер делегирования для Claude Code. Главная (интерактивная) сессия думает и решает, а объёмную рутину выполняют дешёвые воркеры — через LLM-шлюз с моделями GLM/Grok/MiniMax или нативно на подписке Claude (Haiku/Sonnet). Результат возвращается выжимкой со ссылками `файл:строка` или патчем, который применяет человек.

Основная платформа — Windows + PowerShell 5.1. На macOS/Linux скрипты запускаются под pwsh 7 (см. [Установка (macOS)](#установка-macos)), но проверено это только частично.

Порт «схемы оркестратора» (исходная инструкция была под macOS/POSIX sh) на PowerShell.

## О чём этот проект — простыми словами

Вы работаете с Claude Code — это ИИ-ассистент, который помогает писать код прямо в терминале или VS Code. Проблема одна: ассистент «умный, но дорогой» — всё, что он читает (длинные логи, чужой код, большие файлы), оплачивается по тарифу самой мощной модели, и лимит подписки тает на глазах.

Этот проект — несколько коротких команд-помощников. Рутину они отдают дешёвым моделям, а дорогая занимается только сутью задачи:

- `hapy-ask файл` — «перескажи, что здесь важно, и покажи где»: длинный файл превращается в короткую выжимку с номерами нужных строк;
- `glm-task scout "найди, где…"` — поиск и разведка в коде;
- `glm-task start "сделай черновик…"` — черновик правки, который вы потом сами проверите и примените;
- `hapy-review` — «второй взгляд»: вашу правку проверяет модель другого семейства и замечает то, что автор пропустил.

Что для этого нужно: подписка Claude (Pro/Max) — помощники работают внутри неё и тратят лимит совсем медленно. Если есть ещё доступ к шлюзу hapy (сервер с дешёвыми моделями) — экономия и качество проверки становятся ещё лучше, но это не обязательно.

Как начать: [установите проект](#установка-windows) (несколько минут), затем в обычном терминале наберите `hapy-ask README.md` — и получите выжимку этого файла. Привычная работа с Claude Code не меняется: просто появляются новые команды.

## Зачем это нужно

Главная сессия работает на дорогой модели, и всё, что попало в её контекст, оплачивается на каждом следующем ходу: прочитали лог на 3000 строк — и он «висит» в контексте до конца сессии, умножаясь на каждый запрос. Оркестратор разрывает эту связку и экономит токены и деньги сразу по трём линиям:

- **Сырой материал не попадает в контекст основной сессии.** Логи, дампы, чужой код и большие диффы читает дешёвый воркер, а основная модель получает только выжимку на пару экранов со ссылками `файл:строка`. Файл на 50 КБ токенов превращается в выжимку на 2 КБ — контекстное окно живёт дольше, и каждый следующий ход дешевле.
- **Дешёвая модель на дешёвой работе.** «Найди, где в коде используется X», «перескажи этот конфиг», «черновик правки по готовой схеме» — это работа Haiku/GLM/MiniMax-класса, она в разы дешевле работы топовой модели. Платить за неё тарифом основной модели незачем.
- **Оплата идёт там, где дешевле.** На шлюзе работа воркеров тарифицируется по дешёвым моделям; на подписке Haiku жжёт общую квоту на порядок медленнее, чем жгла бы основная модель с тем же материалом в контексте.

Бонус не про деньги: **оппонент из другого семейства** (Grok/GLM против Claude-кода) ловит ошибки, к которым модель-автор слепа.

Итог: решения и приёмка — на дорогой модели; таскание материала — на дешёвых. Счёт за токены падает кратно, а окно контекста основной сессии расходуется только на суть задачи.

## Состав

| Команда | Роль | Модель по умолчанию |
| --- | --- | --- |
| `claude-mode hapy\|claude\|status` | переключение бэкенда **основной сессии** (после Reload Window) | — |
| `hapy-ask файл [файл…]` / `-Text` / stdin | digest: выжимка материала, ≤40 строк, ссылки `file:line` | glm-5.3-flash (шлюз) / haiku (нативно) |
| `glm-task scout "задача"` | разведка кода по снимку репозитория, только чтение | glm-5.3 (шлюз) / haiku (нативно) |
| `glm-task start "задача"` | черновик правки в снимке → патч в `patches/` | glm-5.3 (шлюз) / sonnet (нативно) |
| `hapy-review -Spec … -Diff …` | оппонент: вердикт и замечания по ТЗ и/или диффу | авто: glm-5.3 (<8 КБ) / grok-4.7 (шлюз); sonnet (нативно) |

У `hapy-ask`, `hapy-review`, `glm-task` есть `-Backend auto|gateway|claude`:
`auto` = шлюз, если в `~/.claude/settings.hapy.json` прописан env шлюза (адрес и токен без плейсхолдеров), иначе нативный `claude -p`. Режим `claude-mode` основной сессии оркестратору безразличен.

## Правила оркестрирования

1. **Асимметрия объёма и решения.** Делегируется то, где материала много, а решения мало: логи, выгрузки, чужой код, большие диффы, рутина. Вопросы, решения, приёмка, мелкие правки — основная сессия делает сама.
2. **Не делегируется никогда:** принятие решений, приёмка результатов, секреты (токены, ключи, пароли), общение с внешним миром (коммиты, пуши, деплой).
3. **Одна строка вслух.** Каждый вызов инструмента печатает, какая модель и какой бэкенд выбраны и сколько материала уходит («digest: haiku (backend: claude, material: 1352 chars)»).
4. **Выборочная проверка.** Ответ внешней модели не принимается на веру: 2–3 ссылки `файл:строка` открываются и сверяются. Воркер может ошибаться уверенно.
5. **Патч применяет человек** (или основная сессия по явной просьбе): `git apply --check` → `git apply`. Воркер никогда не касается рабочей копии.
6. **Оппонент — из другого семейства.** Ревью тем ценнее, чем сильнее модель оппонента отличается от автора кода. Нативный оппонент (Claude против Claude) — запасной вариант; если шлюз доступен, ревью идёт через него.
7. **Счётчикам токенов шлюза не верить** — они приблизительные; оплата идёт по факту на стороне шлюза.
8. **Решение и последняя инстанция — всегда у человека.** Воркеры возвращают черновики и мнения, не решения.

## Установка через Claude Code

Самый простой путь на новой машине: откройте Claude Code в любом каталоге и напишите ему:

> Установи оркестратор из https://github.com/S1mkin/ai-orchestrator — следуй файлу INSTALL.md в репозитории. Адрес шлюза: `https://…`, токен: `hapy_…`

Он склонирует репозиторий, сам поставит всё через `install.ps1` и проверит работу. Не хотите передавать токен через чат — просто не указывайте его: Claude Code спросит, как вам удобнее (можно и вовсе без шлюза, тогда установится только нативный бэкенд). Что именно будет сделано — в [INSTALL.md](INSTALL.md). Ручной путь — ниже: [Windows](#установка-windows), [macOS](#установка-macos).

## Установка (Windows)

Требования: PowerShell 5.1 (есть из коробки), Git for Windows (`git` + `tar`), VS Code с расширением Claude Code (или `claude` в PATH). Для нативного бэкенда — подписка Claude (Pro/Max): один раз `claude` → `/login`.

```powershell
git clone <url> ai-orchestrator
cd ai-orchestrator
.\install.ps1                # спросит адрес шлюза и токен; -NoToken = только нативный бэкенд
```

Установщик копирует скрипты в `~/.claude/bin` (и добавляет его в PATH), профили в `~/.claude-glm` и `~/.claude-worker`, варианты настроек в `~/.claude/settings.hapy.json` и `settings.claude.json`, подставляет адрес шлюза вместо `__HAPY_BASE_URL__` и токен вместо `__HAPY_TOKEN__`.

Повторный запуск безопасен: уже настроенные файлы (в которых не осталось плейсхолдеров `__HAPY_*`) не перезаписываются, снимки и патчи не трогаются; обновляются скрипты, промпты и настройки воркеров из репозитория.

Проверка: в новом терминале `claude-mode status`, `hapy-ask README.md`, `glm-task scout "что-нибудь" -MaxTurns 5`.

## Установка (macOS)

Основная платформа разработки — Windows; на macOS всё запускается под кросс-платформенным **pwsh 7**, но проверялось лишь частично — ожидайте шероховатостей и сообщайте о них.

1. `brew install powershell git` (или установите pwsh с сайта Microsoft);
2. `git clone <url> && cd ai-orchestrator`;
3. `pwsh ./install.ps1 -BaseUrl <адрес шлюза> -Token <ключ>` (или `-NoToken`, чтобы жить только на нативном бэкенде);
4. добавьте скрипты в PATH и повесьте алиасы:

   ```sh
   echo 'export PATH="$PATH:$HOME/.claude/bin"' >> ~/.zshrc
   alias hapy-ask='pwsh $HOME/.claude/bin/hapy-ask.ps1'
   ```

   (либо вызывайте напрямую: `pwsh ~/.claude/bin/hapy-ask.ps1 файл`);
5. проверка: `pwsh ~/.claude/bin/hapy-ask.ps1 README.md`.

Что должно работать на macOS: шлюзовой бэкенд целиком (HTTP/SSE и запуск воркеров — переносимый .NET-код: `$HOME` вместо `USERPROFILE`, прямые слэши в путях), `claude-mode`, установщик (PATH добавляется вручную). Что написано, но **не проверялось**: нативный бэкенд — ветка запуска `claude` напрямую через stdin-пайп вместо cmd.exe есть в `hapy-lib.ps1` (`Send-CCMessage`), тестов на реальном Mac не было.

## Шлюз hapy на новой машине

hapy — LLM-шлюз с Anthropic-совместимым API: Claude Code говорит с ним как с обычным Anthropic-сервером, а тот проксирует запросы к моделям GLM/Grok/MiniMax. Подключение на машине, где шлюз никогда не использовался, — два независимых шага: первый достаточен для оркестратора, второй (по желанию) переводит на шлюз саму основную сессию.

**Что понадобится:** адрес шлюза (`https://…`) и персональный токен вида `hapy_…` — их выдаёт администратор шлюза или личный кабинет. Нет токена — оркестратор всё равно работает: ставьте с `-NoToken` и используйте `-Backend claude`.

**1. Воркеры через шлюз.** `install.ps1 -BaseUrl … -Token …` подставит адрес и токен в два файла: `~/.claude/settings.hapy.json` (конфиг шлюза для `hapy-ask`/`hapy-review`) и `~/.claude-glm/settings.json` (профиль воркеров `glm-task`). Основная сессия при этом не меняется. Проверка: `hapy-ask README.md` — в строке статуса должно быть `backend: gateway`.

**2. Основная сессия через шлюз (по желанию).** `claude-mode hapy` — настроенный вариант копируется в живой `~/.claude/settings.json` (env `ANTHROPIC_BASE_URL`/`ANTHROPIC_AUTH_TOKEN`, модель по умолчанию `glm-5.3`, список моделей для `/model`), затем Reload Window (Ctrl+Shift+P). Теперь и основная сессия идёт через шлюз — модели GLM/Grok/MiniMax, оплата по тарифам шлюза, а не по подписке. Вернуться на встроенные модели: `claude-mode claude` + Reload Window. Текущий режим подскажет `claude-mode status`.

Токен после установки хранится в `settings.hapy.json` и `~/.claude-glm/settings.json`, а после шага 2 — ещё и в живом `settings.json`. При ротации обновите его вручную во всех файлах: повторный запуск `install.ps1` уже настроенные файлы не перезаписывает.

## Как устроено

- **Шлюзовой бэкенд:** HTTP SSE на `/v1/messages` шлюза (стриминг обязателен — без него длинные генерации падают с 504). Адрес и токен читаются из `settings.hapy.json` при каждом вызове; в репозитории вместо них плейсхолдеры.
- **Нативный бэкенд:** безголовый `claude -p` в изолированном профиле `~/.claude-worker`. Подписной логин в изолированный профиль сам не виден, поэтому раннер при каждом запуске копирует туда свежий `~/.claude/.credentials.json`; токена шлюза в этом профиле нет.
- **Изоляция воркеров задач** (`glm-task`): работа только в снимке `git archive HEAD`; секретные файлы (`.env`, `config.inc.php`, ключи…) удаляются из снимка; контент-скан на секретоподобные строки — при любом совпадении запуск отменяется, а совпадения печатаются маской (первые 4 символа); профили с allow-списком только на чтение и deny на push/commit/сеть/`rm`; канон (`CLAUDE.md`/`AGENTS.md`) только для чтения. OS-песочницы на родном Windows нет — стены прикладные.
- **Секреты наружу не идут и не возвращаются:** материал выжимки/ревью сканируется перед отправкой, а ответ воркера — перед выводом в консоль; при совпадении вывод маскируется, полный текст остаётся файлом внутри снимка.

## Настройка под себя

- промпты digest/opponent: `profiles/glm/prompts/*.txt` (после установки — `~/.claude-glm/prompts/`);
- порог авто-выбора модели ревью (8 КБ) и сами модели: `bin/hapy-review.ps1`;
- allow/deny воркеров: `profiles/*/settings.json`;
- список исключений контент-скана `$scanExclude` в `bin/glm-task.ps1` — сейчас настроен под проект с MODX (публичный дистрибутив исключён, свой код сканируется); под другой проект скорректируйте.

## Ограничения

- Основная платформа — Windows + PowerShell 5.1. macOS/Linux: через pwsh 7, шлюзовой бэкенд должен работать, нативный не проверялся (см. [Установка (macOS)](#установка-macos)).
- Команды — PowerShell-скрипты: из PowerShell (включая pwsh) запускаются напрямую, из чистого `cmd.exe` — нет (понадобятся .cmd-обёртки, в комплект не входят).
- `claude-mode` меняет env основной сессии только после перезагрузки окна VS Code.
- Нативные воркеры тратят ту же квоту подписки (окна 5 ч / неделя), что и основная сессия — экономия в том, что Haiku жжёт её на порядок медленнее, а сырой материал не попадает в контекст основной сессии.
- Контент-скан эвристический: бывают ложные срабатывания (файл или каталог добавляют в исключения/чистку) и, теоретически, пропуски. Это стена от случайности, а не защита от целенаправленной эксфильтрации.
