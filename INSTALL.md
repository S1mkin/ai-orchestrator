# INSTALL.md — установка силами Claude Code (инструкция для агента)

Этот файл — инструкция для агента (Claude Code), которого пользователь попросил
установить этот набор на новую машину. Выполняйте шаги по порядку; всё, чего не
знаете, спрашивайте у пользователя, а не придумывайте.

## 0. Определите окружение

- ОС: Windows — PowerShell 5.1 есть из коробки; macOS/Linux — нужен pwsh 7
  (`brew install powershell` или установщик с сайта Microsoft).
- Проверьте `git --version` и `tar --version`. Чего-то нет — попросите
  пользователя поставить и остановитесь.
- `claude --version`: если CLI нет, но стоит расширение Claude Code для VS Code —
  это нормально (нативному бэкенду `claude` понадобится, предупредите, если его нет).

## 1. Соберите данные шлюза

Оркестратор работает и без шлюза (нативный бэкенд на подписке), поэтому сами
спросите пользователя В ЧАТЕ (не ждите, что он напишет данные первым): есть ли
доступ к шлюзу hapy, и если есть — пусть назовёт адрес (`https://…`). Адрес —
не секрет, чат для него подходит.

Токен по умолчанию НЕ проходит через чат — пользователь вводит его в своём
терминале:

1. спросите в чате про шлюз и адрес (см. выше);
2. ставьте с `-NoToken -BaseUrl <адрес>` (шаг 2) — адрес подставится в конфиги
   сразу, плейсхолдером останется только токен;
3. попросите пользователя выполнить в СВОЁМ терминале: `orch-set-token` —
   скрипт спросит только токен (в pwsh 7 ввод замаскирован) и сам подставит
   его во все файлы; значение не попадёт ни в чат, ни в историю сессии, ни в
   командную строку;
4. после подтверждения пользователя проверьте: `orch-check -Live` — вы увидите
   маску токена и статус, но не сам токен.

Нет шлюза или адрес не дали — ставьте просто с `-NoToken`: адрес позже задаёт
`orch-set-gateway -BaseUrl <адрес>` (адрес — не секрет, агент может запустить
её сам), токен — `orch-set-token` в терминале пользователя.

Быстрый путь — только если пользователь сам предложил прислать токен в чат:
передайте его в `install.ps1 -Token …` и честно предупредите, что токен
останется в локальной истории сессии этой машины и у провайдера модели, через
которую идёт сессия. Токен не повторяйте в чате лишний раз и не записывайте в
файлы репозитория.

Никогда не запускайте сами `install.ps1` без параметров и `orch-set-token`
без `-Token`: интерактивные запросы (Read-Host) не сработают в
неинтерактивном шелле агента — их выполняет пользователь в своём терминале.
`orch-set-gateway` агенту запускать можно — адрес не секрет. Для install.ps1:
либо оба параметра (`-BaseUrl` и `-Token`), либо `-NoToken` (можно с
`-BaseUrl`).

## 2. Склонируйте и установите

Каталог клонирования спросите у пользователя (по умолчанию `~/ai-orchestrator`)
и склонируйте репозиторий туда.

Установщик пишет в `~/.claude` — это конфигурация самого Claude Code, и защита
прав (авто-режим) может запретить АГЕНТУ её менять. Запрет правильный, НЕ
обходите: попробуйте запустить установщик один раз сами, а при блокировке
сразу передайте команду пользователю в его терминал.

Пробует агент (из каталога клона; без шлюза уберите `-BaseUrl`):

Windows:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File install.ps1 -NoToken -BaseUrl <адрес>
```

macOS/Linux:

```sh
pwsh -NoProfile -File install.ps1 -NoToken -BaseUrl <адрес>
```

Заблокировано — соберите пользователю ГОТОВУЮ команду для его терминала
(подставьте путь клона и адрес; на Windows — обычный PowerShell) и дождитесь
подтверждения, например:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File C:\Users\name\ai-orchestrator\install.ps1 -NoToken -BaseUrl https://gw.example
```

Повторный запуск безопасен: уже настроенные файлы (без плейсхолдеров
`__HAPY_*`) не перезаписываются. Если пользователь выбрал быстрый путь (токен
в чате) — вместо `-NoToken` передайте `-BaseUrl <адрес> -Token <токен>`.

## 3. Проверьте установку

Запустите проверку здоровья (файлы, конфиги, PATH; с `-Live` — ещё короткий
запрос к шлюзу):

```powershell
& "$HOME/.claude/bin/orch-check.ps1" -Live
```

Ожидание: все строки `[ok]` / `[..]` и итог `ALL OK`. Строка `[FAIL]` —
исправьте по подсказке в ней (частые случаи: `__HAPY_*` плейсхолдеры — вернитесь
к шагу 2; PATH — откройте новый терминал или перезапустите install.ps1). Если
запуск orch-check тоже заблокирован — попросите пользователя выполнить его в
своём терминале.

Нативный бэкенд (если пользователь на подписке Claude): нужен один вход
`claude` → `/login`, затем `& "$HOME/.claude/bin/orch-check.ps1" -Native`.

## 4. Расскажите пользователю, что дальше

- Windows: команды видны в любом **новом** сеансе PowerShell, включая
  встроенный терминал VS Code: установщик добавил каталог в PATH (реестр) и
  защищённую строку в профиль PowerShell, которая дописывает PATH при старте
  каждого шелла (терминалы VS Code наследуют окружение самого процесса VS
  Code, а оно старее установки). Если в конкретном окне команд всё ещё нет —
  полностью закройте ВСЕ окна VS Code и запустите его заново (Reload Window не
  перезапускает процесс), либо зовите по полному пути:
  `& "$HOME\.claude\bin\orch-check.ps1"`.
- Единая точка входа — `ai-orch <подкоманда>` (справка: `ai-orch -h`):
  `ai-orch check -Live`, `ai-orch set-token`, `ai-orch set-gateway -BaseUrl …`,
  `ai-orch update -Apply`. Прямые команды (`hapy-ask`, `glm-task`, `orch-check`…)
  работают так же — диспетчер лишь перенаправляет.
- macOS/Linux: установщик PATH не меняет — добавьте в `~/.zshrc` (или
  `~/.bashrc`) строку `export PATH="$PATH:$HOME/.claude/bin"` и при желании
  алиасы вида `alias hapy-ask='pwsh $HOME/.claude/bin/hapy-ask.ps1'`
  (согласуйте с пользователем; без алиасов из zsh/bash скрипт запускается
  только так: `pwsh ~/.claude/bin/hapy-ask.ps1 …`).
- Основная сессия Claude Code не переключалась: чтобы вести и её через шлюз —
  `claude-mode hapy` + Reload Window (необязательно).
- Ничего не коммитьте в клон репозитория.

## 5. Обновления

Позже пользователь может попросить словами «проверь обновления оркестратора»
или «обнови оркестратор». Это делается командами `orch-update` (сравнить
установленную версию с GitHub) и `orch-update -Apply` (git pull в клоне +
переустановка; настроенные файлы с токеном не перезаписываются). После
обновления полезно прогнать `orch-check`.
